## 1. المقدمة

### 1.1 نظرة عامة
الوثيقة تصف نظامًا محاسبيًا مكتبيًا يعمل وفق نموذج عميل/خادم ويغطي الحسابات العامة، الذمم المدينة والدائنة، النقدية والبنوك، الضرائب، مراكز التكلفة، والتقارير المالية مع قابلية توسعة لاحقة.

### 1.2 أهداف النظام
- ضبط الدورة المحاسبية من إدخال القيد وحتى إعداد التقارير الختامية.
- تحسين سرعة ودقة التقارير المالية.
- توفير طبقات أمان وتدقيق عالية لتلبية المتطلبات الرقابية.
- تمكين التكامل مع أنظمة الطرف الثالث مستقبلًا.

### 1.3 الجمهور المستهدف
- الإدارة التنفيذية والمالية لاتخاذ قرارات الاستثمار.
- فريق التطوير لفهم تفاصيل المتطلبات والمعمارية.
- المدققون الداخليون والخارجيون لفحص الضوابط المالية.

### 1.4 التعاريف والاختصارات
- **GL**: الحسابات العامة.
- **AR/AP**: الذمم المدينة/الدائنة.
- **FA**: الأصول الثابتة.
- **UAT**: اختبارات قبول المستخدم.
- **RTO/RPO**: زمن الاستعادة/نقطة الاستعادة المستهدفة.

## 4. الوصف العام للنظام

### 4.1 سياق النظام
النظام يتفاعل مع المستخدمين عبر تطبيق WPF، ويتواصل مع خادم قاعدة البيانات عبر طبقة خدمات أعمال، مع إمكانية إضافة واجهة برمجية (Web API) للتكامل مع أنظمة أخرى مثل CRM أو ERP.

### 4.2 المستخدمون الرئيسيون وأدوارهم
- **محاسب القيود**: إدخال القيود اليومية ومراجعتها.
- **محاسب المبيعات/المشتريات**: إدارة فواتير AR/AP وسندات التحصيل/الصرف.
- **أمين الصندوق**: إدارة الصناديق والشيكات.
- **مدير مالي**: اعتماد القيود، إقفال الفترات، استعراض التقارير.
- **مدقق داخلي**: الاطلاع على السجلات والتقارير الرقابية.
- **مسؤول النظام**: إدارة المستخدمين والصلاحيات والنسخ الاحتياطية.

### 4.3 بيئة التشغيل
- **العميل**: Windows 10/11، .NET 6 Desktop Runtime، شاشة ≥ 1080p.
- **الخادم**: Windows Server 2016 أو أعلى، SQL Server 2014 Standard، IIS (لخدمات التكامل المستقبلية)، Active Directory اختياري.

### 4.4 القيود التصميمية
- الالتزام بـ .NET 6 (أو Framework 4.8) لأسباب توافقية.
- استخدام Entity Framework 6/EF Core مع إمكانية اللجوء إلى ADO.NET للعمليات الثقيلة.
- دعم اللغتين العربية والإنجليزية.

## 5. المتطلبات الوظيفية التفصيلية

### 5.1 الحسابات العامة (GL)
1. إنشاء وتعديل وإلغاء تنشيط الحسابات ضمن بنية هرمية تصل إلى 6 مستويات.
2. تعريف السنوات والفترات المالية مع حالات (مفتوح، مغلق، مجمد).
3. إدخال القيود اليومية مع التحقق اللحظي من التوازن ودعم مراكز التكلفة والعملات.
4. ترحيل القيود مع توثيق المستخدم والتاريخ، وإمكانية إلغاء الترحيل وفق الصلاحيات.
5. تنفيذ قيود التسوية والتسويات البنكية والتسويات الختامية تلقائيًا أو يدويًا.
6. استخراج ميزان مراجعة ودفاتر الأستاذ حسب الفترة، العملة، مركز التكلفة.

### 5.2 الذمم المدينة (AR)
1. إدارة بطاقات العملاء وشروط الدفع وحدود الائتمان.
2. إنشاء فواتير المبيعات والإشعارات الدائنة والمدينة والمرتجعات.
3. تسجيل سندات القبض النقدية والبنكية والشيكات وربطها بالفواتير.
4. إعداد تقارير أعمار الديون والتحصيلات المتوقعة.

### 5.3 الذمم الدائنة (AP)
1. إدارة بطاقات الموردين وشروط التوريد والضرائب.
2. تسجيل فواتير المشتريات والإشعارات وسندات الصرف النقدية والبنكية.
3. تسوية فواتير الموردين وتتبع أرصدة الديون وأعمارها.

### 5.4 النقدية والبنوك
1. تعريف الصناديق والحسابات البنكية وربطها بالمستخدمين.
2. إدارة الشيكات الواردة والصادرة وتتبع حالات التحصيل/الصرف.
3. تنفيذ المطابقة البنكية عبر واجهة مخصصة وإصدار تقارير الفروقات.

### 5.5 الضرائب والقيمة المضافة
1. تعريف كودات الضرائب ونسبها وربطها بالحسابات المناسبة.
2. احتساب الضرائب تلقائيًا على الفواتير والقيود ذات الصلة.
3. إصدار تقارير التوريد والخصم وفق متطلبات الجهات الضريبية.

### 5.6 الأصول الثابتة (مرحلة ثانية)
1. تعريف الأصول ومواقعها ومراكز تكلفتها.
2. إعداد جداول الإهلاك حسب طرق متعددة (ثابت، متناقص، إلخ).
3. معالجة بيع/شطب الأصول وترحيل فروقات الإهلاك.

### 5.7 التقارير المالية
1. قوائم مالية قياسية (الدخل، الميزانية، التدفقات النقدية) قابلة للتخصيص.
2. تقارير تحليلية لمراكز التكلفة والعملات والأداء الشهري.
3. تصدير التقارير إلى PDF وExcel مع دعم المرشحات والباركود.

### 5.8 إدارة النظام والتدقيق
1. إنشاء المستخدمين، الأدوار، والصلاحيات الدقيقة وصولًا إلى مستوى السجل.
2. تسجيل جميع الأنشطة (إنشاء، تعديل، حذف، ترحيل، تسجيل دخول) في سجل تدقيق.
3. إعداد مهام نسخ احتياطي مجدولة واستعادة البيانات من النسخ الاحتياطية.

## 7. المتطلبات المعمارية (SAD)

### 7.1 البنية المنطقية
```
Presentation (WPF/WinForms, MVVM)
    ↓ ViewModels, Validators
Application Services (C# Class Library)
    ↓ Commands/Queries, DTOs, Mappers, Business Rules
Data Access Layer (EF Core/EF6, Repositories, Unit of Work)
    ↓ SQL Server 2014 (Tables, Views, Stored Procedures)
Integration Layer (REST/Web API, Message Queue اختياري)
```

### 7.2 البنية الفيزيائية
- **طبقة العميل**: حواسيب المستخدمين متصلة بالشبكة الداخلية، تحديث عبر ClickOnce/MSI.
- **طبقة التطبيق**: خادم تطبيق Windows يحضن خدمات الأعمال وواجهة API مستقبلية.
- **طبقة البيانات**: خادم SQL Server مع قاعدة بيانات أساسية وبيئة اختبارات منفصلة.
- **طبقة النسخ الاحتياطي**: خادم تخزين (NAS) أو خدمة سحابية لاستيعاب النسخ الاحتياطية.

### 7.3 الأنماط المعتمدة
- MVVM في الواجهة الرسومية.
- Dependency Injection عبر Microsoft.Extensions.DependencyInjection أو Autofac.
- CQRS للتقارير الثقيلة (Queries) مقابل المعاملات (Commands).
- Repository & Unit of Work حيث يلزم التحكم بالمعاملات.

### 7.4 استراتيجيات الاتصال
- ORM عبر EF مع Lazy/Eager Loading مضبوط.
- ADO.NET وإجراءات مخزنة للتقارير المعقدة.
- إمكانية استهلاك خدمات REST خارجية لأسعار الصرف.

### 7.5 سيناريوهات استخدام رئيسية

| معرف السيناريو | الوصف | الممثلون | الأحداث الرئيسية |
| --------------- | ------ | -------- | ----------------- |
| UC-GL-01 | إنشاء وترحيل قيد يومي | محاسب القيود، مدير مالي | إدخال القيد → التحقق من التوازن → حفظ → طلب ترحيل → اعتماد |

## 8. نموذج البيانات (ERD منطقي)

### 8.1 الكيانات الرئيسية
- **ChartOfAccounts**(AccountId PK, Code NVARCHAR(50) UNIQUE, Name NVARCHAR(200), Level INT, ParentId FK→ChartOfAccounts, AccountType TINYINT, IsPostable BIT, Status TINYINT).
- **FiscalYears**(FiscalYearId PK, Name, StartDate, EndDate, Status) و **FiscalPeriods**(PeriodId PK, FiscalYearId FK, Name, StartDate, EndDate, Status).
- **JournalEntries** و **JournalLines** مع تحقق التوازن وعدم ازدواج المدين/الدائن في السطر الواحد.
- **Customers**, **Suppliers**, **Banks**, **CashBoxes**, **CostCenters** لدعم العمليات المحاسبية.
- **ARInvoices**, **APInvoices**, **ARReceipts**, **APPayments** مع العلاقات اللازمة للحسابات.
- **TaxCodes**, **TaxTransactions** لاحتساب الضرائب وتتبعها.
- **Users**, **Roles**, **Permissions**, **AuditLogs** لدعم الأمن والتدقيق.

### 8.2 قواعد التكامل والقيود
- فرض مفاتيح خارجية للسلامة المرجعية بين القيود والحسابات والفترات.
- تفعيل Cascade Update/Restrict Delete حسب الحاجة (مثلاً منع حذف حساب مرتبط بحركات).
- إنشاء فهارس مركبة على الحقول (JournalDate, FiscalPeriodId)، (AccountId, CostCenterId)، (DocDate, Status).
- قيود تحقق CHECK لضمان التوازن وعدم إدخال قيم سالبة غير منطقية.

### 8.3 أمثلة SQL
```sql
CREATE TABLE JournalEntries (
  JournalId INT IDENTITY PRIMARY KEY,
  JournalNo NVARCHAR(30) NOT NULL,
  JournalDate DATE NOT NULL,
  FiscalPeriodId INT NOT NULL REFERENCES FiscalPeriods(PeriodId),
  CurrencyId INT NOT NULL REFERENCES Currencies(CurrencyId),
  Description NVARCHAR(500) NULL,
  IsPosted BIT NOT NULL DEFAULT 0,
  PostedBy NVARCHAR(100) NULL,
  PostedOn DATETIME NULL,
  SourceModule NVARCHAR(10) NULL,
  ReferenceNo NVARCHAR(50) NULL
);

CREATE TABLE JournalLines (
  LineId INT IDENTITY PRIMARY KEY,
  JournalId INT NOT NULL REFERENCES JournalEntries(JournalId),
  AccountId INT NOT NULL REFERENCES ChartOfAccounts(AccountId),
  CostCenterId INT NULL REFERENCES CostCenters(CostCenterId),
  Description NVARCHAR(300) NULL,
  Debit DECIMAL(18,3) NOT NULL DEFAULT 0,
  Credit DECIMAL(18,3) NOT NULL DEFAULT 0,
  CurrencyId INT NULL REFERENCES Currencies(CurrencyId),
  FxRate DECIMAL(18,6) NULL,
  CONSTRAINT CHK_DebitCredit CHECK (NOT (Debit > 0 AND Credit > 0))
);
```

```sql
CREATE PROCEDURE PostJournal @JournalId INT AS
BEGIN
  SET NOCOUNT ON;

  IF (
    SELECT ROUND(SUM(Debit), 3) - ROUND(SUM(Credit), 3)
    FROM JournalLines WHERE JournalId = @JournalId
  ) <> 0
  BEGIN
    RAISERROR(N'القيد غير متوازن', 16, 1);
    RETURN;
  END;

  UPDATE JournalEntries
  SET IsPosted = 1,
      PostedOn = GETDATE(),
      PostedBy = SYSTEM_USER
  WHERE JournalId = @JournalId;

  INSERT INTO AuditLogs(EntityType, EntityId, Action, OldValue, NewValue, PerformedBy, PerformedOn)
  VALUES(N'Journal', @JournalId, N'Post', NULL, NULL, SYSTEM_USER, GETDATE());
END;
```

## 9. تصميم طبقة الأعمال (C#)

```csharp
public class JournalService
{
    private readonly AccountingContext _db;
    private readonly IPeriodPolicy _periodPolicy;

    public JournalService(AccountingContext db, IPeriodPolicy periodPolicy)
    {
        _db = db;
        _periodPolicy = periodPolicy;
    }

    public async Task<int> CreateAsync(JournalEntry entry, string userId)
    {
        if (!_periodPolicy.IsOpen(entry.FiscalPeriodId))
            throw new InvalidOperationException("الفترة مغلقة");

        if (!entry.Lines.Any())
            throw new InvalidOperationException("قيد فارغ");

        decimal totalDebit = entry.Lines.Sum(l => l.Debit);
        decimal totalCredit = entry.Lines.Sum(l => l.Credit);

        if (Math.Round(totalDebit, 3) != Math.Round(totalCredit, 3))
            throw new InvalidOperationException("القيد غير متوازن");

        entry.CreatedBy = userId;
        entry.CreatedOn = DateTime.UtcNow;

        _db.JournalEntries.Add(entry);
        await _db.SaveChangesAsync();
        return entry.JournalId;
    }

    public async Task PostAsync(int journalId, string userId)
    {
        await _db.Database.ExecuteSqlRawAsync("EXEC PostJournal @p0", journalId);

        var audit = new AuditLog
        {
            EntityType = "Journal",
            EntityId = journalId.ToString(),
            Action = "Post",
            PerformedBy = userId,
            PerformedOn = DateTime.UtcNow
        };
        _db.AuditLogs.Add(audit);
        await _db.SaveChangesAsync();
    }
}
```

## 10. تصميم واجهات المستخدم

### 10.1 المبادئ العامة
- واجهات تعتمد تصميم MVVM مع ValidationRules للإدخال.
- دعم اللغتين العربية والإنجليزية وتغيير الاتجاه ديناميكيًا.
- توفير لوحة تحكم تعرض مؤشرات رئيسية (KPIs) مثل التدفقات النقدية، أعمار الذمم، هوامش الربح.

### 10.2 الشاشات الأساسية
1. **شاشة القيد اليومي**: Grid لإدخال السطور مع البحث السريع عن الحسابات ومراكز التكلفة، عرض تراكمي للمدين/الدائن.
2. **إدارة الفترات المالية**: فتح/إغلاق/تجميد مع سجل أحداث.
3. **شاشات AR/AP**: إنشاء فاتورة أو سند عبر Wizard بسيط، إرفاق المستندات، متابعة حالة السداد.
4. **النقدية والبنوك**: تتبع الصناديق، الشيكات، والأوامر، مع عرض حالة كل شيك.
5. **التقارير**: عارض تقارير RDLC/DevExpress مع إمكانية التصدير والطباعة.
6. **الإعدادات**: إدارة المستخدمين، الأدوار، معايير النظام، وإعدادات النسخ الاحتياطي.

### 10.3 قابلية الوصول والاستخدام
- اختصارات لوحة مفاتيح للعمليات اليومية (F5 للحفظ، Ctrl+P للطباعة، إلخ).
- رسائل خطأ متسقة وواضحة، مع اقتراح الحلول عند الإمكان.
- دعم البحث المتقدم والتصفية في كل الشبكات (Grids).

### 12.1 المصادقة والتفويض
- دعم الهوية المدمجة مع إمكانية التكامل مع Active Directory.
- سياسات كلمات المرور (الحد الأدنى للطول، التعقيد، انتهاء الصلاحية، قفل الحساب).
- إدارة جلسات الدخول، تسجيل الخروج التلقائي بعد فترة خمول.

### 12.2 التدقيق والأرشفة
- سجل تدقيق مهيكل مع القيم القديمة والجديدة وتفاصيل المستخدمين.
- أرشفة المرفقات في نظام ملفات أو مخزن كائنات مع صلاحيات منفصلة.
- إمكانية استخراج تقارير تدقيق لعمليات حساسة (ترحيل، حذف، تغيير صلاحيات).

### 12.3 النسخ الاحتياطي والتعافي
- Full Backup يومي، Differential كل 6 ساعات، Log Backup كل 15 دقيقة.
- حفظ النسخ في موقعين (On-Premises وOffsite/S3).
- اختبارات استعادة ربع سنوية موثقة.

## 13. التكامل والتبادل

- **استيراد بيانات**: ملفات CSV/Excel للعملاء والموردين، أرصدة افتتاحية، دليل الحسابات.
- **تصدير بيانات**: تقارير PDF/Excel، إمكان الربط مع Power BI عبر Views وStored Procedures.
- **واجهات برمجية مستقبلية**:
  - `POST /api/ar/invoices`
  - `POST /api/ap/invoices`
  - `GET /api/gl/trial-balance?from=...&to=...`
- استخدام Message Queue (RabbitMQ أو Azure Service Bus) للعمليات المتزامنة اختياريًا.

## 14. الأداء والاختبارات

### 14.1 استراتيجيات الأداء
- فهارس مركبة، Partitioning اختياري لجداول القيود الكبيرة.
- Cache للقواميس (الحسابات، المراكز، العملات) باستخدام MemoryCache.
- Pagination افتراضي في كل الاستعلامات الجدولية.

### 14.2 خطة الاختبار
1. **اختبارات وحدات**: تغطية الخدمات وقواعد العمل الأساسية باستخدام xUnit/NUnit.
2. **اختبارات تكامل**: محاكاة رحلة القيد الكامل وواجهة المستخدم عبر UI Automation.
3. **اختبارات الأداء**: سيناريوهات تحميل حتى 200 مستخدم باستخدام أدوات مثل JMeter (عبر API أو خدمة وسيطة).
4. **اختبارات أمن**: تقييم صلاحيات المستخدم، فحص حقن SQL، اختبار اختراق داخلي.
5. **UAT**: سيناريوهات مقبولة تشمل القيد متعدد العملات، إقفال فترة، دورة فاتورة عميل كاملة، تقرير ميزان مراجعة.
