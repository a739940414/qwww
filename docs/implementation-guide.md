# دليل تنفيذ وتشغيل النظام المحاسبي

يوضح هذا الدليل كيفية تشغيل نسخة أولية من النظام المحاسبي المبني في هذا المستودع باستخدام ‎.NET 6‎ وSQL Server 2014.

## 1. المتطلبات المسبقة

1. تثبيت ‎.NET 6 SDK‎ على محطة التطوير.
2. توفير خادم SQL Server 2014 (أو إصدار أحدث متوافق) مع صلاحية إنشاء قواعد بيانات.
3. تحديث سلسلة الاتصال في ملف `src/Accounting.Api/appsettings.json` لتشير إلى الخادم المناسب.

## 2. إعداد قاعدة البيانات

1. أنشئ قاعدة بيانات فارغة (مثلًا: `AccountingDb`).
2. حدِّث قيمة `AccountingConnection` في ملف الإعدادات لتتضمن اسم الخادم وقاعدة البيانات وبيانات الاعتماد.
3. عند تشغيل واجهة الـAPI لأول مرة ستُنفَّذ الترحيلات (Migrations) تلقائيًا وسيُضاف الحد الأدنى من البيانات المرجعية (العملات، دليل الحسابات الأساسي، مراكز التكلفة، الضريبة).

> **ملاحظة**: في بيئة الإنتاج يفضَّل تنفيذ الترحيلات يدويًا عبر `dotnet ef database update` ضمن عملية نشر مُحكَمة.

## 3. تشغيل واجهة الـAPI

1. من مجلد `src/Accounting.Api` نفِّذ الأمر:
   ```bash
   dotnet run
   ```
2. في أول تشغيل سيُنشئ التطبيق قاعدة البيانات (إن لم تكن موجودة) ويضيف البيانات الأولية.
3. ستتوفر وثائق Swagger على الرابط `https://localhost:5001/swagger` (أو المنفذ المعتمد في بيئتك).

## 4. المصادقة التجريبية

* يمكن الحصول على رمز JWT تجريبي باستدعاء نقطة النهاية `POST /api/auth/token` وتمرير بيانات تسجيل الدخول التالية:
  ```json
  {
    "username": "admin",
    "password": "P@ssw0rd!"
  }
  ```
* الرمز الناتج صالح لمدة 8 ساعات ويُستخدم ضمن ترويسة `Authorization: Bearer <token>` للوصول إلى بقية واجهات الـAPI.
* يجب استبدال هذا النهج في الإنتاج بآلية مصادقة فعلية (مثل ASP.NET Identity أو التكامل مع Active Directory).

## 5. وحدات النظام المتاحة حاليًا

* **دليل الحسابات**: إنشاء، تحديث، وتعطيل الحسابات.
* **القيود اليومية**: إنشاء القيد مع التحقق من التوازن وترحيله.
* **العملاء والموردون**: إدارة البطاقات الأساسية تمهيدًا لعمليات الذمم.

الطبقات الأخرى (الفواتير، السندات، التقارير) ممهدة عبر نموذج البيانات ويمكن إكمالها تباعًا.

## 6. تخصيص الإعدادات

* ملف `appsettings.json` يحتوي إعدادات الاتصال وقيم JWT.
* يمكن إضافة ملف `appsettings.Development.json` (مستثنى من التحكم بالنسخ) للاستخدام المحلي.
* لتغيير سياسات القيود أو التحقق يمكن تعديل الخدمات داخل مشروع `Accounting.Application`.

## 7. الاختبارات والتوسعة

* يوصى بإضافة مشروع اختبارات (xUnit/NUnit) للتحقق من خدمات الأعمال.
* يمكن توسيع الواجهات بإضافة وحدات مثل فواتير المبيعات والمشتريات باستخدام نفس الأنماط.
* لدعم واجهة سطح مكتب WPF، يمكن استهلاك خدمات الـAPI الحالية أو إضافة مشروع عميل جديد ضمن الحل.

## 8. نشر الإنتاج

1. إعداد ملف إعدادات مخصص للبيئة الإنتاجية مع اتصال SQL Server مؤمَّن.
2. استخدام `dotnet publish` لإنتاج حزمة قابلة للنشر (على IIS أو Kestrel خلف عاكس).
3. تفعيل HTTPS (شهادات موثوقة) ومراقبة سجلات التطبيق وقاعدة البيانات.
4. جدولة نسخ احتياطي لقاعدة البيانات بحسب السياسة الموضحة في وثيقة التحليل.

> للمزيد من التفاصيل حول المتطلبات والعمليات راجع وثيقة `docs/accounting-system-srs.md`.
